# BalanceHub — схема выпусков

## Версии
- Последняя стабильная версия: 1.2.0 (публичный GitHub Latest).
- Обычные изменения: 1.2.1-rc1, -rc2, -rc3 ... затем утверждённая 1.2.1.
- Крупные изменения (по согласованию): 1.3.0-rc1, -rc2 ... затем 1.3.0.
- Target задаётся как NEXT_RELEASE_VERSION в gradle.properties.
- GitHub Actions вычисляет следующий rcN по **опубликованным** prerelease тегам этого target, начиная с rc1. Номера не переиспользуются.
- Android versionCode в подписанной сборке увеличивается с номером GitHub Actions run. applicationId и ключ подписи остаются прежними.

## Тестовая сборка
- После утверждённых изменений pull request объединяется в main; workflow собирает APK с версией NEXT_RELEASE_VERSION-rcN.
- Компиляция, lint, JVM-тесты, тестовая Android APK, подписанная APK, проверка сертификата и инструментальные тесты API 29/35/36 обязательны перед публикацией.
- Сначала APK загружается во временный Draft; размер, SHA-256 и метаданные проверяются **до публикации**. Затем выпускается публичный **Pre-release**, доступный по постоянным ссылкам.
- Прямая ссылка: https://github.com/RussoTurissto/BalanceHub/releases/download/vX.Y.Z-rcN/BalanceHub.apk
- Страница: https://github.com/RussoTurissto/BalanceHub/releases/tag/vX.Y.Z-rcN
- Старые RC не удаляются и не перезаписываются.
- Встроенный обновлятор использует /releases/latest и отвергает prerelease, поэтому не предлагает RC обычным пользователям.

## Стабильный релиз
- Только после явного утверждения владельцем.
- Подготовить и утвердить release/notes-X.Y.Z.md с коротким текстом для приложения.
- Вручную запустить Build BalanceHub update APK на main с publish_stable=true и approved_version=X.Y.Z (точное совпадение с NEXT_RELEASE_VERSION).
- Workflow требует существующий публичный rc, собирает новую подписанную APK с versionName=X.Y.Z и более высоким versionCode и повторно проверяет тот же commit на эмуляторах.
- Публикация идёт через временный Draft с проверкой SHA-256 и завершается публичным Release с Latest. Стабильный тег и активы не перезаписываются.
- После выпуска следующую обычную цель поменять на X.Y.(Z+1), либо на X.(Y+1).0 для крупных правок.

## Безопасность
- Не публиковать APK, если подпись, хеш или тесты не прошли.
- Не публиковать стабильную версию автоматически при обычном push или RC.
- Не делать APK артефактом публичного GitHub Actions (прямая ссылка предоставляется через публичный Pre-release).
- Старые закрытые Draft/rollback сохраняются в истории, штатные RC начиная с 1.2.1 публикуются открыто.
- APK ставится поверх предыдущей версии. Удаление приложения может привести к утрате локальных данных.

## Передача в чат
После успешной публикации ассистент сообщает страницу выпуска и прямой URL APK. Дополнительно можно приложить APK в чат, только если удалось действительно получить его байты в текущей сессии и проверить SHA-256.
